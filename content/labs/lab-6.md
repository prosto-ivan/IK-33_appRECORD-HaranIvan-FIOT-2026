# Лабораторна робота №6: Документування API за допомогою Swagger. Деплой Node.js-додатку

**Тема:** Документування API за допомогою Swagger, деплой Node.js-додатку, підсумковий проєкт REST API з базою даних.

**Мета:**  
Навчитися документувати REST API за допомогою Swagger/OpenAPI, інтегрувати Swagger UI у Node.js + Express застосунок, описувати endpoint-и, параметри та моделі даних, а також підготувати Node.js-додаток до деплою на хмарний сервіс.

---

## ⚙️ Завдання 1. Створення REST API на Node.js + Express

**Було необхідно:**
- створити або використати REST API на Node.js та Express;
- перевірити запуск серверного застосунку;
- переконатися, що API доступне через HTTP-запити.

**Результат:**
У межах лабораторної роботи було використано вже розроблений серверний застосунок `LinkEduHub`, створений на основі Node.js та Express. Проєкт містить REST API для авторизації користувачів, роботи з навчальними ресурсами, ролями, типами ресурсів, статусами користувача, профілем та іншими функціями.

Сервер запускається через команду `npm start` або `node server.js`. Після запуску застосунок відкриває порт і стає доступним для обробки HTTP-запитів.

![Запуск сервера](/assets/labs/lab-6/server_start.png)

## 🗄 Завдання 2. Підключення бази даних та реалізація CRUD-операцій

**Було необхідно:**
- підключити базу даних до серверного застосунку;
- реалізувати CRUD-операції;
- перевірити роботу API для створення, отримання, оновлення та видалення даних;
- показати, що серверна частина працює з даними через REST API.

**Результат:**
У проєкті `LinkEduHub` використовується база даних, підключена до Node.js-застосунку через ORM `Sequelize`. Основна структура бази даних складається з таблиць користувачів, ролей, навчальних ресурсів, типів ресурсів та статусів навчання користувачів.

У межах лабораторної роботи було використано вже реалізовані CRUD-операції для навчальних ресурсів. Вони дозволяють отримувати список ресурсів, переглядати один ресурс за ID, створювати новий ресурс, редагувати існуючий ресурс та видаляти ресурс.

Основні CRUD endpoint-и для роботи з ресурсами:

```text
GET /api/resources
GET /api/resources/:id
POST /api/resources
PUT /api/resources/:id
DELETE /api/resources/:id
```

Маршрут `GET /api/resources` використовується для отримання всіх навчальних ресурсів. Він доступний для перегляду та повертає список ресурсів у форматі JSON.

Маршрут `GET /api/resources/:id` дозволяє отримати конкретний ресурс за його ідентифікатором.

Маршрути `POST /api/resources`, `PUT /api/resources/:id` та `DELETE /api/resources/:id` використовуються для створення, редагування та видалення ресурсів. Ці дії доступні лише адміністратору, оскільки вони захищені middleware для перевірки токена та ролі користувача.

![CRUD-маршрути ресурсів у коді](/assets/labs/lab-6/crud_routes_code.png)

Для перевірки роботи API було виконано запит на отримання списку ресурсів. Сервер повертає JSON-відповідь зі списком навчальних ресурсів, що підтверджує роботу підключення до бази даних і REST API.

![Перевірка отримання ресурсів](/assets/labs/lab-6/resources_get_result.png)

## 📘 Завдання 3. Інтеграція Swagger UI у проєкт

**Було необхідно:**
- встановити бібліотеки для роботи зі Swagger;
- створити конфігурацію Swagger/OpenAPI;
- підключити Swagger UI до Express-застосунку;
- перевірити відкриття документації API у браузері.

**Результат:**
Для документування REST API у проєкт було інтегровано Swagger UI. Для цього були встановлені бібліотеки `swagger-ui-express` та `swagger-jsdoc`.

У проєкті було створено окремий файл конфігурації Swagger, у якому описано основну інформацію про API: назву, версію, опис, сервери та схеми авторизації. Swagger використовує стандарт OpenAPI 3.0.0, що дозволяє автоматично формувати документацію на основі опису endpoint-ів.

```text
docs/swagger.js
```

У файлі `server.js` Swagger UI було підключено за маршрутом:

```text
/api-docs
```

Після запуску сервера документація API стала доступною у браузері за адресою:

```text
https://linkedu-web-2026-2.onrender.com/api-docs
```

або локально:

```text
http://localhost:3000/api-docs
```

## 🧾 Завдання 4. Документування endpoint-ів API

**Було необхідно:**
- задокументувати основні endpoint-и REST API;
- описати HTTP-методи, параметри, request body та responses;
- додати Swagger-коментарі до маршрутів;
- описати захищені маршрути з використанням JWT-авторизації.

**Результат:**
У проєкті було виконано документування основних endpoint-ів API за допомогою Swagger-коментарів у форматі OpenAPI. Документація була додана безпосередньо до файлів маршрутів, зокрема до `authRoutes.js` та `resourceRoutes.js`.

У Swagger-документації було описано дві основні групи endpoint-ів:

```text
Auth
Resources
```

До групи `Auth` належать endpoint-и, пов’язані з реєстрацією, авторизацією та профілем користувача:

```text
POST /api/auth/register
POST /api/auth/login
GET /api/auth/profile
```

До групи `Resources` належать endpoint-и для роботи з навчальними ресурсами:

```text
GET /api/resources
GET /api/resources/{id}
POST /api/resources
PUT /api/resources/{id}
DELETE /api/resources/{id}
```

Для POST- та PUT-запитів було описано `requestBody`, тобто структуру JSON-даних, які користувач має передати на сервер. Для маршрутів, які потребують авторизації, додано схему `bearerAuth`, що дозволяє передавати JWT-токен через Swagger UI.

![Swagger-коментарі для Auth endpoint-ів](/assets/labs/lab-6/swagger_auth_docs.png)

![Swagger-коментарі для Resources endpoint-ів](/assets/labs/lab-6/swagger_resources_docs.png)

Після додавання Swagger-коментарів endpoint-и автоматично відобразилися у Swagger UI. У документації можна побачити доступні маршрути, методи запитів, параметри, приклади body та можливі відповіді сервера.

![Список endpoint-ів у Swagger UI](/assets/labs/lab-6/swagger_endpoints_list.png)

## 🚀 Завдання 5. Демонстрація підсумкового проєкту та деплой Node.js-додатку

**Було необхідно:**
- підготувати Node.js-додаток до деплою;
- додати `start`-script у `package.json`;
- налаштувати використання змінної середовища `PORT`;
- завантажити проєкт на GitHub;
- виконати деплой на хмарний сервіс;
- перевірити доступність застосунку через публічний URL.

**Результат:**
Проєкт `LinkEduHub` було підготовлено до деплою на платформу Render. Для цього у файлі `package.json` було додано script запуску серверного застосунку:

```json
"start": "node server.js"
```

У файлі `server.js` порт було налаштовано через змінну середовища. Це необхідно для хмарного середовища, оскільки Render самостійно задає порт, на якому має працювати застосунок.

```js
const PORT = process.env.PORT || 3000;
```

Також запуск сервера було налаштовано так, щоб він слухав адресу `0.0.0.0`, що потрібно для коректної роботи на Render.

```js
app.listen(PORT, '0.0.0.0', () => {
    console.log(`✅ Сервер запущено: http://0.0.0.0:${PORT}`);
});
```

Після підготовки проєкт було завантажено на GitHub та підключено до Render. На Render було виконано автоматичне встановлення залежностей через `npm install` та запуск застосунку командою `npm start`.

У логах Render видно, що сервер успішно запустився на наданому платформою порту, а застосунок став доступним за публічним URL.

```text

```

Серверна частина застосунку була успішно опублікована та запущена на Render, однак підключення до хмарної БД потребує додаткового налаштування користувача, прав доступу та початкових даних. У межах лабораторної роботи було продемонстровано деплой Node.js-сервера, доступність публічного URL та роботу Swagger UI.
